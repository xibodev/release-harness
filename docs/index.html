THE MODEL

Accept intent. Bind execution. Seal what happened.

The contract says what must hold. Bindings say where to look. Keeping those identities separate lets one proposition run locally and in CI without changing its meaning.

  1. 01AuthorDraft + evidence record
  2. 02AcceptImmutable proposition
  3. 03ExecuteHTTP or CLI binding
  4. 04AdjudicateSeal + verify chain

A missing executable, unreachable endpoint, unresolved reference, or harness fault cannot become a PRODUCT accusation because of text printed by a process. Attribution is structural and conservative.

EXIT CONTRACT

Five exits. No ambiguous green.

Automation receives the same decision a person reads.

0
PASS

An eligible certifying run held.

Verify the chain; promotion remains your decision.
1
ASSERTION VIOLATED

A reached subject violated an accepted assertion.

Investigate the subject.
2
UNPROVEN

A draft is blocked or a run is exploratory.

Resolve evidence or semantic questions.
3
USAGE / CONTRACT / BINDING

Nothing valid was executed.

Correct the declaration or binding.
4
HARNESS / INTEGRITY

The run or its evidence cannot be trusted.

Preserve and investigate the evidence.
GET STARTED

Nothing is assumed at install time.

init installs the protocol and empty authoring space. It does not infer your subject, ports, URLs, repository roles, or assertions.
